# 自分専用の参考書づくり

教科書(PDF・写真)を読み、**自分が理解するための解説**を LaTeX で書いて PDF にするフォルダ。
読者は、この分野を学んでいる途中の本人。式を追えるように、途中式を省かず、行間を言葉で埋める。

## 役割分担

| 段階 | 担当 | 道具 |
|---|---|---|
| ① 読む(画像 → テキスト+LaTeX) | ローカルの Qwen2.5-VL 72B | `tools/local_read.py` → `ocr/<本>/*.md` |
| ② 書く(解説の文章・構成) | Claude | `notes/<単元>/main.tex` |
| ③ 組版(LaTeX → PDF) | Claude がビルドして直す | `./build.sh notes/<単元>` |
| ④ 検査(式・記号・内容) | Claude(別の目で) | サブエージェント `checker` |

## 守ること

1. **`sources/`(元の教科書)は読むだけ。変更・削除しない。**
2. **教科書の文章を、そのまま長く写さない。** 自分の言葉で言い換え、どこを見たかは `\src{p.63}` で残す。
   数式・定義は、理解に必要な最小限を引用してよい。図は `tools/crop.py` で元画像から切り抜いて貼る
   (描き直すと誤りが入る。TikZで描くのは、切り抜けない概念図だけ)。
3. **`ocr/*.md` の `[?]` は推測で埋めない。** 該当ページの画像を見て確認する。
   画像でも読めないときは、解説には書かず、報告に「読めなかった箇所」として挙げる。
4. **書き始める前に `dict/` を検索する。** 用語・定理・記号が既にあれば再利用し、説明をゼロから作り直さない。
   新しく出てきたものは、単元を書き終えたら `dict/` に追記する。
5. **記法は `dict/notation.md` と `template/preamble.tex` に従う。** 独自のマクロを単元ごとに作らない。
   足りなければ preamble に足し、notation.md も同時に直す。
6. **式は必ず検算する。** 導出・数値・単位・次元を確かめる(下の「検算」)。確かめていない式を断定しない。

## 単元の書き方

`template/unit.tex` を `notes/<単元名>/main.tex` にコピーして始める。構成の型:

1. **この単元で何が分かると嬉しいか**(動機を式より先に。たとえ話を1つ)
2. **考え方**(全体の見通し。図があればここ)
3. **導出**(途中式を省略しない。「なぜこの変形か」を1文ずつ)
4. **具体例**(数値を入れた例を1つ。単位つき)
5. **つまずきやすい所**(`caution`)と **確認問題**(`question`。解答は別の節に)
6. **まとめ**(`point` に3行以内)

ファイル名は `notes/<章>-<節>_<短い題>/main.tex`(例 `notes/2-6_分岐公式/`)。

## ビルド

```
./build.sh notes/<単元>        # 成功: notes/<単元>/<単元>.pdf ができる
./build.sh --all               # 全単元
```

失敗したら、表示された「ファイル:行番号: 原因」を直して再実行する。
**5回直して通らなければ止まり、何が詰まっているかを報告する**(同じ直し方をくり返さない)。
直してよいのは `notes/<単元>/` の中と、必要なら `template/preamble.tex` だけ。

## 検算

計算の確認には sympy を使う。入っていなければ:

```
uv run --with sympy python -c "import sympy as sp; ..."
```

- 微分・積分・展開は sympy で式変形の結果を機械的に確かめる
- 次元(単位)を確かめる。式の両辺で単位が一致しているか
- 極端な場合(r → ∞、対称性、符号)で、結果が物理的に妥当か

## コマンド

- `/note <単元名> <どの本のどこ>` … ①の結果を読み、書き、ビルドし、検査して報告する 1回分の流れ
