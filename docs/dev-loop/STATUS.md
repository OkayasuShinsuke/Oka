# まなびっこ 開発ループ 状態ファイル

30分ごとに自動で起きるループが、会話の記憶に頼らず「次に何をするか」を判断するための
しおりです。ループの1周ごとに、必ずこのファイルを読んでから作業し、最後に更新してください。

## 最優先の判断基準（すべてのタスクに適用）

どのタスクをやるときも、最後にこの3つで自己採点してから終わること。
迷ったら、この3つを一番伸ばす選択肢を選ぶ。

1. **面白さ** — 遊んでいて楽しいか（演出・テンポ・驚き）
2. **やりたくなる中毒性** — また開きたくなるか（毎日の理由、コレクション欲、達成感）
3. **知識の定着** — 遊んだ結果、本当に かず・ひらがな が身につくか
   （派手さだけで内容が薄くならないよう注意）

タスク6「面白さの改善」・7「面白さの評価」は独立項目ではなく、
1〜5のどのタスクをやる時も上の3基準で見直す、という運用にする。

## 並列トラックについて

このアプリ（まなびっこ、幼児向け）と、`docs/dev-loop/ADVANCED_APP.md` の
電磁気・東大数学アプリ（別プロジェクト）は、**同じ30分ループの中で並列に**
進める。触るファイルが完全に別なので同時編集しても衝突しない。
このファイルは、まなびっこ側の状態だけを管理する。

## 優先順位（上から順に）

1. [x] **効果音・音楽をパチンコ風にもっと盛り上げる**（1周目で完了）
   - 既存: `sfx.ok/ng/coin/fever/fanfare`（Web Audio API のトーン合成）と
     フィーバー演出（`.stage.fever`）が `index.html` にある。
   - やること案: 「リーチ」感を出す緊張感のある音（正解発表の直前に鳴る）、
     コンボ中に鳴る短いBGMループ（ミュート可能）、大当たり演出をもっと派手に。
   - 制約: 外部音源ファイルは使わない（1ファイルで完結させたいため）。
     すべて Web Audio API のオシレーターで合成する。
2. [ ] **読み上げ音声を自然にする（無料範囲）**
   - 現状: `speak()` が1文まるごと1つの `SpeechSynthesisUtterance` に渡していて、
     抑揚が単調で棒読みに聞こえる。
   - やること案: 「、」「。」「！」「？」で文を分割し、区切りごとに短い間（pause）を
     入れて複数の utterance をキューで話す。文の種類（褒め言葉/問題文/残念）で
     rate・pitch を少し変える。使える日本語音声の中から一番自然なものを自動選択
     （`speechSynthesis.getVoices()` を見て、可能なら高品質そうな声を優先）。
   - iOS Safari と Android Chrome の両方で確認しづらい点はコメントで明記しておく
     （実機で人間が最終確認する前提）。
3. [ ] **セーブデータの複数端末対応（ひきつぎコード方式）**
   - 方針: アカウント登録はさせない（幼児向けなので）。6桁くらいの「ひきつぎばんごう」
     を発行し、それを別の端末に入力すると同じセーブデータが復元される、キッズ携帯
     ゲームでよくある方式。
   - サーバー側（`server.js`）: `POST /api/save` で今の状態(JSON)を保存して番号を返す。
     `GET /api/save/:code` で番号から状態を取得する。保存先は `data/saves/` 以下の
     JSONファイル1つ1コード（DBは導入しない、個人利用規模のため）。サイズ上限
     （例: 50KB）と簡単なバリデーションを必ず入れる。
   - クライアント側: 設定画面に「ひきつぎばんごう」表示・発行ボタン、別端末用の
     入力欄を追加。今の state（coins, stickers, owned, equip, love, lastFed など）を
     まとめて送受信する関数を作る。
   - 重要な注意: **claude.ai の Artifact プレビュー（プレビュー用リンク）からは
     このサーバーに繋がらない。** この機能が実際に動くのは、`npm start` で
     動かした本物のサーバー経由でアプリを開いたときだけ。ループの各周でこれを
     ユーザーに伝え忘れないこと。
4. [ ] **問題の種類を増やす**（電磁気・東大数学は含まない。幼児向けの範囲で）
5. [ ] **UIの改善**
6. [ ] **面白さの改善**
7. [ ] **面白さの評価**（実装ではなく、遊んでみて良い点/改善点を書き出す）

## 進め方のルール（token-saver スキルに準拠）

- 設計判断はメイン（Opus/このループ本体）が行い、実装は Sonnet サブエージェントに
  1タスク=1依頼で渡す。
- 実装後は Playwright で1回だけスクリーンショット確認（`/tmp/.../scratchpad/` に保存）。
  ループを組んで何度も自己チェックしない。
- 確認できたら `git add -A && git commit && git push origin claude/kids-learning-app-95o37w`。
- 最後に、この STATUS.md の該当項目にチェックを入れ、次回への申し送りを
  「## 直近のログ」に1〜3行で追記する。
