# まなびっこ 開発ループ 状態ファイル

15分ごとに自動で起きるループが、会話の記憶に頼らず「次に何をするか」を判断するための
しおりです。ループの1周ごとに、必ずこのファイルを読んでから作業し、最後に更新してください。

## 最優先の判断基準（すべてのタスクに適用）

どのタスクをやるときも、最後にこの3つで自己採点してから終わること。
迷ったら、この3つを一番伸ばす選択肢を選ぶ。

1. **面白さ** — 遊んでいて楽しいか（演出・テンポ・驚き）
2. **やりたくなる中毒性** — また開きたくなるか（毎日の理由、コレクション欲、達成感）
3. **知識の定着** — 遊んだ結果、本当に かず・ひらがな が身につくか
   （派手さだけで内容が薄くならないよう注意）

タスク6「面白さの改善」・7「面白さの評価」は独立項目ではなく、
1〜5のどのタスクをやる時も上の3基準で見直す、という運用にする。

## ループの終了条件（重要）

- 開始時刻: 2026-09-27 16:04 UTC（6時間後 = 2026-09-27 22:04 UTC で強制終了）。
- **このファイルと `ADVANCED_APP.md` の優先順位リストが両方とも全部 [x] になったら、
  ループ自身が `CronDelete` で自分のジョブを止める。**
- それでも終わらない場合の安全弁として、**ループ開始から6時間経過したら、
  進捗にかかわらず自動的に停止する**（無限に回り続けさせない）。延長したい場合は
  ユーザーが `/loop` を出し直す。
- 停止する周は、最後にユーザー向けの短い進捗まとめ（できたこと・残っていること・
  人間の確認が必要な項目）を書いてから止めること。

## エラー時のバックオフ（重要）

サブエージェントの検証で失敗した（pageerrorが出た、Playwrightでの動作確認が
通らない、`git push` が失敗した、など）場合、**そのタスクの変更はcommitしない**
（壊れた状態をリポジトリに残さない）。そのうえで、このファイル（該当トラックが
まなびっこなら本ファイル、上級アプリなら `ADVANCED_APP.md`）の「直近のログ」に

    - ⚠️ ERROR at <date -u の出力>: <何が失敗したか、原因の見立て>

の形で記録する。**次の周に入ったら、まず両ファイルの直近のログの先頭を見る。**
先頭が ⚠️ ERROR で、その時刻から**1時間経っていなければ**、そのトラックは
今回何もしない（サブエージェントを呼ばない、commitしない）でスキップする。
もう片方のトラックにエラーがなければ、そちらは通常どおり進めてよい
（エラーは基本的にトラックごとに個別対応。両方同時にエラーの場合のみ、
その周は実質何もせず次に回す）。1時間経っていれば、同じタスクを再挑戦してよい
（原因を変えずに同じ実装をもう一度依頼するのではなく、前回のエラー内容を踏まえて
一言でも対策を変えてから依頼すること）。

## 「面白さの評価」の扱い方（重要な限界）

ループ自身（Claude）は「楽しいと感じる」ことができないので、次の2つに分ける。

- **客観チェック（ループが自分でできる）**: エラーが出ないか、報酬演出が毎回
  一律すぎないか（音や演出のバリエーション数を数える）、テンポ（1問あたりの
  待ち時間）、操作の分かりやすさ、正答率が異常に低い/高い問題がないか、など。
  これは実際にPlaywrightで操作して確認してよい。
- **人間の試遊が必要（ループはできない）**: 「本当に楽しいか」「また遊びたく
  なるか」は、実際に遊んだ人（ユーザー・お子さん）の感想でしか分からない。
  ループはこれを勝手に採点しない。かわりに、ある程度タスクが進んだ節目で
  「試してほしいポイント」を3〜5個くらいにまとめてユーザーに渡す。

## 優先順位（上から順に）

1. [x] **効果音・音楽をパチンコ風にもっと盛り上げる**（1周目で完了）
   - 既存: `sfx.ok/ng/coin/fever/fanfare`（Web Audio API のトーン合成）と
     フィーバー演出（`.stage.fever`）が `index.html` にある。
   - やること案: 「リーチ」感を出す緊張感のある音（正解発表の直前に鳴る）、
     コンボ中に鳴る短いBGMループ（ミュート可能）、大当たり演出をもっと派手に。
   - 制約: 外部音源ファイルは使わない（1ファイルで完結させたいため）。
     すべて Web Audio API のオシレーターで合成する。
2. [x] **読み上げ音声を自然にする（無料範囲）**（2周目で完了）
   - 現状: `speak()` が1文まるごと1つの `SpeechSynthesisUtterance` に渡していて、
     抑揚が単調で棒読みに聞こえる。
   - やること案: 「、」「。」「！」「？」で文を分割し、区切りごとに短い間（pause）を
     入れて複数の utterance をキューで話す。文の種類（褒め言葉/問題文/残念）で
     rate・pitch を少し変える。使える日本語音声の中から一番自然なものを自動選択
     （`speechSynthesis.getVoices()` を見て、可能なら高品質そうな声を優先）。
   - iOS Safari と Android Chrome の両方で確認しづらい点はコメントで明記しておく
     （実機で人間が最終確認する前提）。
3. [ ] **セーブデータの複数端末対応（ひきつぎコード方式）**
   - 方針: アカウント登録はさせない（幼児向けなので）。6桁くらいの「ひきつぎばんごう」
     を発行し、それを別の端末に入力すると同じセーブデータが復元される、キッズ携帯
     ゲームでよくある方式。
   - サーバー側（`server.js`）: `POST /api/save` で今の状態(JSON)を保存して番号を返す。
     `GET /api/save/:code` で番号から状態を取得する。保存先は `data/saves/` 以下の
     JSONファイル1つ1コード（DBは導入しない、個人利用規模のため）。サイズ上限
     （例: 50KB）と簡単なバリデーションを必ず入れる。
   - クライアント側: 設定画面に「ひきつぎばんごう」表示・発行ボタン、別端末用の
     入力欄を追加。今の state（coins, stickers, owned, equip, love, lastFed など）を
     まとめて送受信する関数を作る。
   - 重要な注意: **claude.ai の Artifact プレビュー（プレビュー用リンク）からは
     このサーバーに繋がらない。** この機能が実際に動くのは、`npm start` で
     動かした本物のサーバー経由でアプリを開いたときだけ。ループの各周でこれを
     ユーザーに伝え忘れないこと。
4. [ ] **難易度を幼児〜小学3年生まで拡張する**
   - 方針: 今の「やさしい(〜5)/むずかしい(〜10)」の2段階を、5段階に拡張する。
     Lv1 幼児やさしい(〜5) / Lv2 幼児むずかしい(〜10) / Lv3 小1(くり上がり・

   - 目安: レベル選択が5段階になり、レベルごとに実際に問題の内容・難しさが

## 進め方のルール（token-saver スキルに準拠）

- 設計判断はメイン（Opus/このループ本体）が行い、実装は Sonnet サブエージェントに
  1タスク=1依頼で渡す。
- 実装後は Playwright で1回だけスクリーンショット確認（`/tmp/.../scratchpad/` に保存）。
  ループを組んで何度も自己チェックしない。
- 確認できたら `git add -A && git commit && git push origin claude/kids-learning-app-95o37w`。
- 最後に、この STATUS.md の該当項目にチェックを入れ、次回への申し送りを
  「## 直近のログ」に1〜3行で追記する。
