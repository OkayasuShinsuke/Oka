# 上級者向け学習アプリ 状態ファイル（電磁気学・東大数学）

まなびっこ（幼児向け）とは別プロジェクト。ファイルが分かれているので、
まなびっこの改善ループと**同じ30分サイクルの中で並列に**進める。

## 対象・方針（決定事項）

- 対象者: 高校生〜大学院生（電磁気学）、大学受験生（数学・東大入試レベル）。
  **まなびっこの幼児向けデザイン（メンダコ・パステル）は流用しない。**
  落ち着いた、勉強道具として信頼できる見た目にする（サーキット/実験ノート風などを想定。
  実装担当が具体案を出してよい）。
- 設置場所: `public/advanced/index.html`（`public/kids/index.html` と並列の1ファイル構成）。
  `server.js` は `express.static('public')` なのでそのまま両方配信できる。追加のサーバー
  変更は不要（セーブ同期はまなびっこ用に作る `/api/save` 系を将来共用してもよい）。
- 数式表示: KaTeX を使う（CDN: `cdnjs.cloudflare.com/ajax/libs/KaTeX/...`、許可リスト内）。
  自前でLaTeXパーサを書かない。
- 出題方式は科目で使い分ける:
  - **電磁気学**: なるべく「パラメータを乱数で振って、同じ式から答えも自動計算する」
    ジェネレーター方式にする（クーロンの法則、電場・電位、コンデンサ、オームの法則・
    キルヒホッフ則、電磁誘導、交流回路など）。手で数値を打った「別解答」を作らない
    こと（式のズレによる誤答を防ぐため）。
  - **東大入試レベル数学**: 証明・論証を含むため無理に自動生成せず、**厳選した問題を
    手作りで蓄積するバンク方式**にする。1問ごとに、途中式・行間の説明を省略しない
    丁寧な解答をセットで持つ（ユーザーの学習スタイルの好みに合わせる）。単元タグ
    （微積分・数列・確率・整数・ベクトル・複素数平面 など）を必ず付ける。
- **正しさが最優先。** 学習アプリで誤答・誤植は致命的なので、電磁気の自動生成問題は
  「生成に使った式」と「採点に使う式」を同じ関数から出すこと（二重管理しない）。
  数学バンクの問題は、実装後に最低1問は電卓的に検算してから commit する。

## 「面白さ・中毒性・知識の定着」をどう実現するか

- **知識の定着（最優先）**: 間隔反復（かんたんなSM-2風）を入れる。各問題/単元の正誤履歴を
  localStorageに保存し、間違えた・久しぶりの項目を優先的に再出題する。派手な演出よりも
  「ちゃんと間違えた問題に再会する」ことを優先する。
- **やりたくなる中毒性**: 連続学習日数（ストリーク）、XP、苦手単元の可視化（ヒートマップ
  的な一覧）、「今日はあと◯問」の小さな目標設定。ガチャ的な派手さより、Duolingo/Anki
  に近い「積み上げが見える」系の中毒性を狙う（対象が高校生〜大学院生のため）。
- **面白さ**: 正解時の手応え（軽いアニメーション・音）は、まなびっこと同じくWeb Audio API
  のオシレーター合成で作ってよい。ただし演出は幼児向けより控えめ・洗練された方向にする。

## 解説の質（すべての問題に適用する原則）

学習者のレベルを本当に引き上げるため、新規に追加する問題だけでなく既存の問題も
この基準を満たすようにする。

1. **公式の根拠**: 公式を「暗記するもの」ではなく「なぜ成り立つか」が分かる形で
   一言添える（例: クーロンの法則なら、なぜ距離の2乗に反比例するかの直感的説明）。
2. **別解を最低1つ**: 可能な問題には、別の解法・別の公式からのアプローチを
   もう1つ用意する（ユーザーの学習スタイルの希望）。証明が1通りしかない場合は
   「別の見方・検算方法」でもよい。
3. **図解（SVG、外部画像は使わない）**: 電磁気は回路図・電場のようす・ベクトル図、
   数学はグラフ・図形など、式だけでなく絵で見えるようにする。`public/kids/index.html`
   の `tako()` のような、インラインSVGをJSで組み立てるパターンを流用してよい。
4. **用語の一言定義**: 「電位」「条件付き確率」のような専門用語が出たら、初めて
   見る人にも分かる一言説明を添える。

## ループの終了条件・エラー時のバックオフ・「面白さの評価」の扱い

`STATUS.md`（まなびっこ側）と同じルールに従う（詳細はそちらを参照、重複記載しない）。
要点だけ:
- ループ間隔は15分。チェックリスト全部完了 または 開始から6時間経過 のどちらか
  早い方で自動停止する。
- **サブエージェントの検証に失敗したら、このファイルにcommitせず、直近のログに
  `⚠️ ERROR at <時刻>: <内容>` と記録し、1時間はこのトラックを休む**（もう片方の
  トラックにエラーがなければそちらは進めてよい）。1時間経ったら、前回のエラーを
  踏まえて対策を変えてから再挑戦する。
- 「面白さ・中毒性」は客観チェックのみ行い、人間の試遊が必要な項目は最後に
  リストにしてユーザーへ渡す。

## 既知の注意点

- claude.ai の Artifact プレビューリンクでは、KaTeXのCSS（外部スタイルシート）が
  CSPでブロックされ、数式が生のLaTeXテキストのまま崩れて見えることがある。
  `npm start` で動かす本物のサーバー経由なら正しく表示される。ユーザーへの報告で
  このプレビュー版の制限は毎回明記すること（セーブ同期機能の注意と同様の扱い）。

## 進め方のルール

`docs/dev-loop/STATUS.md`（まなびっこ側）と同じ。設計はメインが決め、実装は
Sonnet サブエージェントへ。1周1タスク、Playwrightで1回だけ確認、commit・push、
このファイルを更新。まなびっこ側の作業と**同じループの中で並列に**依頼してよい
（ファイルが重ならないため）。
